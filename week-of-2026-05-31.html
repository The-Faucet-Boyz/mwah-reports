⭐ Highlights of the week
🔀

Store records can now be merged and licenses corrected — no manual workarounds

Two long-standing admin pain points land this week. Managers can now change a store's license number directly on the store record — pick "renewal" to keep the old number in history, or "correction" if it was wrong from day one. Available from the store's Licenses tab, the recon mismatch queue, and buyer correction approvals. Separately, a new Merge Stores tool lets admins fold a duplicate store into the right one: orders, contacts, activities, credits, and chain links all transfer to the surviving record, and the merged store's license stays on as an alias. No more manual database cleanup for duplicate stores or license mistakes.

Admin
🗝️

Full team can now manage the buyer portal queue — no manager required

Field and inside reps can now approve or reject portal registration requests, grant or remove a buyer's store access, and enable or disable accounts. The entire queue that used to be manager-only is now open to the full team — Hannah, Maddie, and everyone on inside sales can work it end-to-end without waiting for a manager to step in. View-as (buyer impersonation for troubleshooting) stays manager-only.

Portal mgmt
🛍️ Buyer portal
📝

Order change options now match where the order actually is

The order page shows the right options based on status. Before a delivery date is locked in, buyers can chat with the team, write out a change in their own words, or request a cancellation. Once scheduled, the order shows a SCHEDULED badge and delivery date. Orders already on their way out show chat only.

Buyer portal
➕

Buyers can add a product to a pending change request

While editing an order, buyers can tap "Add product," pick from the catalog, set the case count, and it joins the change request — with an undo if they change their mind. Products already on the order are filtered out automatically.

Buyer portal
📋

Cancelled orders now appear in Order History

Buyers can filter by "Cancelled" in their Order History and see the cancellation reason on each order's detail page. Deleted orders stay hidden — only genuine cancellations show up.

Buyer portal
📅

Delivery dates from the CRM now show on the portal

When a rep schedules a delivery date in the CRM, the buyer's portal view reflects it immediately and the order shows as SCHEDULED. Previously the date only lived on the rep's side and buyers had no way to see it.

Bug fix
✉️

Order confirmation emails got a full formatting pass

Emails now show real per-line dollar amounts in aligned columns, a single clean Total row, the actual ship-to address with recipient name, and the buyer's real first name in the greeting. The layout renders correctly in Gmail, Outlook, and on mobile.

Bug fix
🔐

Sign-in and password reset fixed across the board

Google sign-in on mobile Safari now completes successfully. Password reset and welcome links land on a branded MWAH page with a clear sign-in button — not a blank Firebase screen. "Wrong email or password" now points directly to the password reset link.

Bug fix
📱

Mobile polish — menus, labels, and product names

The mobile menu now highlights the page you're actually on. Product names on the Shop page wrap fully instead of truncating. "Pending" is now the consistent status label for submitted orders across every portal view.

Buyer portal
👥 Portal management
📌

Sign-up and QR requests now live in the Needs Attention bar

Pending portal sign-up requests and QR registrations now appear as chips inside the Needs Attention bar alongside everything else that needs your attention. They used to show as a separate banner above it — one place covers it all now.

Portal mgmt
📝

New Note Edits tab — catch when buyers update their delivery notes

When a buyer changes a store's delivery notes at checkout, the edit now surfaces in a new Note Edits tab and in the Needs Attention bar. Review it and choose to adopt the change as the store's new standard — or dismiss it as a one-time note.

Portal mgmt
🔍

Requests tab now has filters, search, and pagination

A status filter, date range, and search box make it easy to find specific requests in a long queue. The Pending tab now shows a helpful empty state when there's nothing left to action.

📦 Orders + fulfillment
✉️

Change-request approval emails now show the real order total

The "Your change request was approved" email was going out with "New total: $0.00" — it now shows the actual value of the updated order every time.

Bug fix
✏️

Buyer edits stay visible on the fulfillment board after approval

Once a buyer's change request is approved and updated in GrowFlow, the fulfillment row shows exactly what changed — quantities up or down, items added or removed. Tap the EDITED badge for the full before-and-after history.

Orders
🗑️

Reps can now delete their own test orders and duplicates

No more waiting for a manager to clean up test orders or accidental duplicates — the rep who created the order (or is credited on it) now has the trash button. Portal orders still route through the Cancel flow so buyers get notified.

⚙️ Behind the scenes
  • Portal transactional emails migrated to React Email components — structurally eliminates the Gmail flex-rendering bug class (pill centering, column alignment) that kept resurfacing.
  • CRM Google sign-in on mobile now uses the same same-origin redirect fix that landed on the buyer portal last week — Safari and strict-cookie-mode browsers complete the handshake correctly.
  • Portal auth observability broadened: desktop OAuth redirect failures now trigger the same Sentry alerts as mobile failures (the old tag was missing desktop regressions for weeks).
  • Portal credit page read path fixed: the permissions error that blocked buyers from viewing their store credits was resolved by deriving balances from the credits subcollection directly.
  • Store Detail orders tab: "Delivered" status pill tooltip no longer shifts adjacent table columns on hover.
  • Recon license-mismatch flow hardened: in-place change is now the primary option; succession guard blocks linking to a deleted store; phantom "needs review" rows no longer persist after a decision is resolved elsewhere.
  • Duplicate invoice warning added to the Orders & Fulfillment editors — stops the typo that was generating false "multiple match" rows in the recon queue.
  • Admin permanent-delete for truly empty stores now available (Admin → Deleted Stores). Any store with orders, contacts, credits, or lineage links is blocked and must be merged instead.
