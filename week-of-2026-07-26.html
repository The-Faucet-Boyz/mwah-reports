⭐ Highlights of the week
📧

You can now read teammate emails right from Store Detail — no Gmail connection needed

This one came straight out of the July 21 all-hands. Hannah and Maddie raised it: the Emails tab on a store showed that a teammate had sent something, but you couldn't actually read it unless you were signed in to that person's Gmail account. Now any team member can click a row to expand the full email — from, to, cc, date, the whole message body, and any attachments — right where the row sits. No redirection, no "connect your Gmail" wall, no guessing what was said.

New feature
🔄

The CRM now fixes itself if it gets stuck on the loading screen

A production issue this week left the CRM showing "Loading dashboard..." forever with no error and no way out except clearing browser site data by hand. The root cause was Firestore's offline persistence getting wedged — and since the app sat inside the same stuck client, it couldn't see any problem. The fix adds a lightweight watcher that runs separately from the main app. If the CRM is loading but a quick probe to Firebase answers in milliseconds, that's a wedged local persistence layer, not a network issue — and the app now detects that, clears the lock, and reloads cleanly instead of leaving reps stranded.

Critical fix
🛍️ Buyer portal
📊

Buyers can now see their own inventory analytics in the portal

A new analytics section in the buyer portal shows each store their sell-through trends and stock levels over time. Buyers get context on their own pace directly in the ordering flow, without needing to ask a rep.

New feature
🔁

The reorder experience in the portal got a significant rework

VMI self-service — the page where buyers see reorder suggestions and can approve, adjust, or decline — was rebuilt this week. Navigation is clearer, the layout is tighter, and the state when a store has no current inventory to reorder is now handled gracefully rather than showing a broken view.

Improvement
💬

Reorder recommendation copy is clearer

The language around why a reorder is being suggested was updated to be more straightforward for buyers reading it in context. Less jargon, more plain math.

Polish
🛡️

Portal errors now surface properly

A gap in the portal's error handling meant certain failure states were being swallowed silently — buyers would see a blank or broken page with no explanation. The error handler is now wired in so problems surface with context instead of disappearing.

Bug fix
👥 Portal management & admin
📥

Admins can now import POSaBIT monthly reports for customer mix analytics

A new import tool in the admin panel lets managers bring in completed calendar-month POSaBIT reports — customer demographics, product mix, retailer breakdown. Imports are idempotent (re-uploading the same file is safe) and audited. The data feeds directly into the Insights customer mix view.

New feature
🏷️

POSaBIT retail promotions now show on the store page

Active POSaBIT promotions at a store are now surfaced in Store Detail alongside pricing context. Reps can see what deals are running at each location before a visit or call.

New feature
📦 Orders & fulfillment
🔔

Fulfillment gets pinged when notes are added after a PO is confirmed

If a rep adds a note to an order that's already been confirmed and is heading to fulfillment, the team now gets a Slack alert right away. Post-confirmation notes are exceptions — this makes sure they don't get missed before the order ships.

Improvement
🔗

GrowFlow reconciliation is more resilient to temporary errors

GrowFlow occasionally returns success-looking responses that actually contain an error buried in the body — the kind of thing that should trigger a retry, not a failure. The reconciliation sync now catches those cases and retries, so transient GrowFlow hiccups don't interrupt the daily sync.

Reliability
⚙️ Behind the scenes
  • Portal callables (order creation, product listing, order history) were running sequential network calls one-at-a-time — parallelizing them cut the time-to-data noticeably for buyers in the checkout flow.
  • The portal's Slack alert emails were generating "orphaned event" errors in the monitoring system — a missing audit log tag that's now fixed.
  • A new executable semantic layer formalizes how analytics metrics are defined and queried across MCP, BigQuery, and the OpenClaw bot — ensuring numbers mean the same thing wherever they appear.
  • The projected sales pace calculation was audited and reconciled against the governed metric definition — any surface showing pace now uses one canonical helper.
  • Analytics health guards updated so the Insights page doesn't show misleading numbers when a data source is partially unavailable.
  • Store selector contrast improved in the portal so it's readable on all backgrounds.
  • Decision IDs are now automatically scoped to their PR number, enforced by the pre-commit hook — no more accidental ID collisions when multiple PRs land the same week.
  • Emulator secrets are now isolated so real production credentials can't leak into local test runs.
  • Portal security hardened across several public endpoints — adversarial edge cases from a full security pass are now closed.
  • Dependency updates: firebase-functions 7.3.0, Sentry 10.67.0, Resend 6.18.0, React 19.2.8.
