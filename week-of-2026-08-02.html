⭐ Highlights of the week
🏢

The CRM is becoming a multi-brand platform

This week laid the foundation for the CRM to support multiple brands operating under the same system — each with its own data, users, and settings, but sharing the same infrastructure. A new workspace provisioning flow lets a new brand be set up end-to-end. This is a significant step in where the platform is headed, and most of the work is invisible for now — it's the scaffolding everything else will build on.

Platform expansion
⚡

The CRM is noticeably faster across the board

A coordinated performance sprint this week touched the CRM's boot sequence, the Inventory page, and the Dashboard. The CRM now reaches its first usable screen faster by deferring background work until after the initial paint. The Inventory page was split into separate store and warehouse views so each loads only what it needs. And a group of memory leaks that caused slowdowns in long sessions have been sealed. If the app felt sluggish before, it should feel considerably snappier now.

Performance
👥 Portal management & admin
🤖

VMI reorders can now run on autopilot for trusted stores

A new "pre-authorized" mode for VMI lets you designate stores where inventory suggestions should convert to orders automatically — no rep approval step. When an order goes through, the rep gets a notification. Stores where reps want to review every suggestion still work the same way as before.

New feature
🗂️

POSaBIT now has a dedicated admin tab

POSaBIT sync management has been promoted to its own tab in the admin panel, with store-mapping review built in. You can see which stores are connected, spot any mapping issues, and fix them without hunting through settings.

New feature
📦 Orders & fulfillment
🤝

Volume commitments are now trackable on price groups

You can now set a volume commitment threshold on a price group — when a store hits their agreed purchase level, that's tracked and visible in the credits dashboard. Useful for accounts where a commitment is part of the deal structure.

New feature
🔍

A full GrowFlow-to-CRM reconciliation audit now runs automatically

The reconciliation process now includes a complete cross-reference between GrowFlow's records and every CRM order, surfacing mismatches before they create billing or reporting problems. The monthly audit is also more resilient to edge-case data that previously caused it to stumble.

New feature
📊 Analytics & insights
🧬

Product analytics now show the right numbers

A mismatch in how product identity was tracked was causing some SKUs to appear merged or miscounted in analytics views — making sold-per-day and product performance numbers unreliable for affected items. Fixed, so the Insights product breakdown reflects what actually sold.

Bug fix
💳

Credits dashboard is cleaner and more readable

Range display and tooltips on the credits dashboard were showing incorrect or confusing values in certain views. The Discounts activity credit totals also now display the right amount. Both are cleaned up.

Bug fix
🌐 Public website (gimmemwah.com)
📍

Newsletter signups now show where subscribers are from

The sign-up form now captures your approximate state (WA, CA, etc.) at the point of signup, so the team can see geographic distribution across the subscriber list without anyone having to fill in a field manually.

New feature
📈

Better understanding of what drives engagement on the site

Privacy-minimized Mixpanel analytics were added to gimmemwah.com — no PII, no session recording — so the team can see which pages and features drive the most interaction. Reporting quality was also hardened to make the data more reliable.

New feature
🔎

The site shows up more accurately in Google search

A pass on the site's indexing signals cleaned up duplicate and conflicting meta tags. The UTM campaign link builder was also aligned with the current campaign taxonomy, so links generated for marketing campaigns track correctly.

Improvement
⚙️ Behind the scenes
  • CRM boot critical path trimmed — non-essential work now defers until after first paint, reducing time-to-usable-screen.
  • Inventory page split into dedicated store and warehouse routes — each loads only the data it needs, cutting page weight significantly.
  • Dashboard and inventory memory leaks sealed — long sessions no longer accumulate invisible overhead that slowed things down over time.
  • VMI alert targeting fixed — alerts were firing for too many stores; now they fire only for stores actively enrolled in VMI.
  • Initial invoice assignment alerts quieted — startup was generating alert noise before the first sync completed.
  • CRM batch view fixes: stage labels now display correctly, duplicate stockout rows removed, per-rep activity colors working again.
  • Email health retries made durable and idempotent — the retry system was occasionally triggering double-runs on transient failures.
  • Portal analytics now exclude "view-as" sessions where reps are browsing in buyer mode — buyer-facing metrics are cleaner as a result.
  • Deploy self-heal: when Cloud Functions hit a Cloud Run CPU quota ceiling during deploy, affected functions are now automatically detected and re-deployed without any manual intervention.
  • Google Sheets Apps Script for signup tracking automated via CI, with several data-mapping and column-ordering fixes so Sheet rows are accurate and complete.
  • Dependency updates: Playwright 1.62.0, MCP SDK, pdfkit 0.19.1, Sentry Node 10.68.0, svix 1.99.1.
