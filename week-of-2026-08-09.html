⭐ Highlights of the week
💰

You can now see what each store owes — in the CRM

A new Accounts Receivable surface is live in the CRM, giving reps and managers a direct view of outstanding balances by store. No more cross-referencing spreadsheets or waiting for a finance update — what's owed is now visible right where you're already working with stores.

New feature
↩️

Returns are now part of the reconciliation workflow

When a store returns product, that return is now visible, creditable, and closable directly inside the reconciliation interface. Previously, returns required manual workarounds outside the system. They're now a first-class part of the process — you can see them, apply a credit, and close them out, all in one place.

New feature
🛍️ Buyer portal
🔐

Locked-out buyers see a clear message instead of a confusing error

When a buyer tries to sign in but their account isn't active, they now see a clear explanation — instead of a generic data error that made it look like something was broken.

UX improvement
🛒

Stalled carts are managed more reliably

The menu for closing or managing a stalled cart was sometimes unreachable. That's fixed. Carts where the store has already placed an order through the rep are now also closed automatically, so they don't linger as false "pending" activity.

Bug fix
⏰

Abandoned cart follow-ups now run reliably

The automated sweeps that follow up on abandoned carts were hitting their own concurrency limits and stopping early. They now run to completion every time.

Bug fix
📦 Orders & fulfillment
🤝

Deal settlements are now detected and exported correctly

When a deal is baked into an invoice, the system now detects it and includes a dedicated Deal Settlement block in the monthly export. Reps and managers can see exactly what was settled and on which invoice.

New feature
🔔

Reconciliation alerts are now reliable and won't fire twice

The alerts that fire when reconciliation needs attention were sometimes going quiet or triggering multiple times for the same issue. They're now durable — they fire once, stay visible until resolved, and clear cleanly.

Bug fix
📋

GrowFlow settlement and return handling fixed

The way GrowFlow settlement entries and rejected returns were being processed had edge cases that caused mismatches. The matching logic is now more accurate, so those edge cases no longer produce phantom discrepancies.

Bug fix
📊

Monthly export is more accurate

The monthly export now reflects only paid reps in commission figures, carries a list-price caveat where relevant, and has cleaner copy throughout. Less manual cleanup after you download it.

Improvement
🧃

Fulfillment flavor order is now consistent

The order flavors appeared in on the fulfillment view wasn't matching the expected sequence. It's aligned now.

Bug fix
📊 Analytics & insights
💳

Credits ledger is now visible again

The ledger view and kind-breakdown bands in the credits dashboard were failing to render. They're back and displaying correctly.

Bug fix
📣

GrowFlow daily alerts are easier to act on

The GrowFlow daily alerts were formatted in a way that made it hard to scan quickly. They're now structured for speed — the most important information surfaces at a glance so you can act without digging.

Improvement
🔍

Insights metrics are more clearly labeled

Several metrics in the Insights view had labels or dashboard context that didn't make their meaning obvious. They've been clarified so it's easier to know what you're looking at and what it's telling you.

Improvement
👥 Portal management & admin
🪪

License changes route through one guided flow

There used to be two ways to update a store's license in the admin panel — a quick-link card and a guided modal — which caused confusion about which to use. The quick-link card is retired; everything now goes through the guided modal, where the intent (renewal vs. correction) is clear.

Improvement
✏️

Sales reps can now update store name and address

Reps in the Sales role were blocked from editing a store's name or address, even for obvious corrections. That restriction has been relaxed — reps can now keep store info accurate without needing an admin to step in.

Improvement
📦 Inventory (POSaBIT)
📈

Inventory now shows 6-week and 8-week sales velocity

The Avg Sales/Day figure on inventory snapshots now comes in two additional windows — 6 weeks and 8 weeks — alongside the existing shorter window. Useful for spotting seasonal trends or smoothing out one-off weeks when deciding how much to reorder.

New feature
🔗

POSaBIT sync is more reliable

The sync was occasionally timing out silently, leaving data stale with no indication of what happened. It now surfaces the issue clearly. A separate re-link prompt that kept nagging even after a successful link is also gone.

Bug fix
🌐 Public website (gimmemwah.com)
🗺️

California stores now appear on the locator

MWAH's California retail accounts are now included in the store locator feed on gimmemwah.com. California customers can now find where to buy, just like Washington customers.

New feature
🛍️

Products now have their own dedicated page

A proper product listing page is live at gimmemwah.com/products — with individual flavor pages for Berry Baddie and Glow Up Grape. A mobile locator bug that emerged alongside this work has also been fixed.

New feature
🔎

The site is more discoverable in search

A pass on meta tags, canonical signals, GA4 key events, and page structure makes the site more accurately represented in Google search results. AI crawlers also get a cleaner picture of what MWAH is and does.

Improvement
📧

Signup tracking is smarter

The signup capture flow now enriches each subscriber entry with lifecycle data — so the team can understand how someone moved from first capture to confirmed subscriber, making the list more useful for follow-up.

Improvement
⚙️ Behind the scenes
  • firebase-admin 13 → 14 migration completed — 3 production Cloud Functions and 44 scripts now on the latest admin SDK.
  • Entire Cloud Functions fleet, CI pipeline, and local dev tooling moved to Node.js 24.
  • Firestore indexes now deploy before the code that queries them — previously a new index could ship after the code, causing runtime errors in the gap.
  • Smoke test false positives fixed — a healthy backend-only deploy was being flagged as a failure; shallow-clone git diffs were being read as "no changes."
  • Weekly audit backlog cleared and recurring findings are now automated — a scheduled check catches the same categories going forward without manual review.
  • CI required checks made resilient: checks no longer fail when main moves under a PR, and the skip gate fails closed when the branch has no qualifying history.
  • BigQuery client upgraded to v9 in MCP — breaking-change migration done.
  • Upcoming flavor SKUs registered in the product catalog for the Ops mirror — guarded so they remain non-orderable until officially activated.
  • Recon "Skip" decision now accurately reflected in the Decisions tab — previously showed stale state after a single skip.
  • Mixpanel pilot added to the private SEO reporting pipeline — site behavior data now feeds into weekly search performance reports.
  • Dependency updates: @playwright/test 1.62.1, firebase 12.17.1, firebase-functions 7.3.2, @sentry/node 10.69.0, googleapis 174.0.1, resend 6.18.1.
