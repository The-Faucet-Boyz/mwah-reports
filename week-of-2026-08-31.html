⭐ Highlights
🔁

Buyers can now reorder from any past order

The buyer portal now shows a "Suggested Reorder" section based on previous purchases, and every past order in Order History has a quick reorder action. Buyers can rebuild a familiar order in seconds without starting from scratch — a big time-saver for stores that run the same mix every cycle.

Buyer portal
♿

Full WCAG AA color and button accessibility pass

Every color, text contrast, and button state across all three CRM themes now meets WCAG AA standards. This was a comprehensive sweep — not just a handful of spots — so the entire app reads cleanly for everyone on the team, including on lower-brightness screens.

Visual / design
🛍️ Buyer portal
🚦

Order minimum applies to buyers, not rep proposals

The order minimum now only blocks buyers at checkout — reps putting together proposals aren't gated. This means reps can draft small test orders or sample builds without hitting a wall, while buyers still see the minimum enforced when they place their own orders.

New behavior
📋

VMI proposals can't go below the order minimum

When a buyer adjusts a vendor-managed inventory proposal, the edit is now floored at the order minimum. No more accidentally approving a proposal that would come in under the minimum.

VMI
✨

New flavors get a better label in VMI

Flavors that just launched now show "New flavor — try it out!" in vendor-managed inventory suggestions instead of being flagged as a "Slow mover." Much more accurate for a brand-new SKU that hasn't had time to build a sales history.

VMI
📦 Orders + fulfillment
🏳️

Bulk flag and unflag orders in fulfillment

Ops can now select multiple orders at once and flag or unflag them in bulk — no more clicking through orders one by one when something needs to be marked for follow-up or cleared after review.

Fulfillment
🔒

Completed orders stay locked in their fulfillment week

A routing bug was causing completed orders to get re-sorted out of a locked fulfillment week when the view refreshed. Fixed — a completed order now stays exactly where it landed.

Fulfillment
📜

28 stuck Jul 29 orders are visible again + full list loads

A batch of 28 orders from the July 29 fulfillment cycle were stuck and not showing in the All view. They're restored. The All view also no longer silently cuts off at 500 orders — the full list loads now.

Fulfillment
📱 Dashboard + analytics
🔬

Daily automated data-quality sweep

A new daily probe runs automatically and reports any data integrity issues to #crm-audit. Catches problems before they surface as wrong numbers or missing records — the team sees issues proactively, before anyone has to go looking.

Data quality
📊

Samples Given Out chart now shows full history

The Samples trend chart in Analytics was only showing the past month. It now loads the full history, so you can see the long-term samples arc and compare against earlier periods.

Analytics
⚠️

App tells you when data might be capped

If the live data cache hits its saturation limit, the app now surfaces a visible notice rather than silently showing a partial dataset. You'll know when you're looking at incomplete data instead of guessing.

Transparency
🌐 Public website
🗺️

Store locator switched to OpenFreeMap

The Find Us map now uses OpenFreeMap instead of CartoDB. Loads faster, has no API key dependency, and includes full fallback handling if the map fails — so the store list always stays usable even without the visual map.

gimmemwah.com

Washington and California discovery pages

Two new state hub pages went live — one for Washington shoppers, one for California. Each page helps people searching for MWAH in their state find the right retailers, with structured data for search engines to pick up.

gimmemwah.com

Homepage controls its own search snippet

Individual flavor descriptions were leaking into Google's preview snippet for the site, making search results look like a product list instead of a brand homepage. Fixed — the homepage now surfaces clean summary copy in search.
