⭐ Highlights
📦

Inventory got a full overhaul — the numbers finally add up, and working the queue is much faster

This was a big week for Inventory. The By Product view was rebuilt from the ground up with POSaBIT data parity — you now see a runway bar, order tiles, and performance tiles side by side so everything you need to decide on a reorder is in one place. Tab counts now show actual work items. The sidebar badge counts stores with a problem, not just emails sent. Proposals & Emails got a multi-select status filter with Expired finally exposed. And a switched-off product no longer ghosts its way onto CRM surfaces after it's been pulled.

Inventory
🌸

MWAHcha is now front and center on the homepage — the new kits have their moment

gimmemwah.com now leads with a coming-soon hero for MWAHcha kits, with a "See the Line" link and a CTA pointing customers to their nearest store. The hero is fully optimized for mobile. This is the first time MWAHcha has had a dedicated homepage presence — customers landing on the site will know something exciting is coming.

gimmemwah.com
📦 Inventory + proposals
📊

By Product view rebuilt with side-by-side POSaBIT data

The Inventory By Product view was rebuilt to match what POSaBIT shows — you now see a runway bar, a current-order tile, and a performance tile together, so the decision to reorder (or not) is visible without hunting across tabs.

Inventory
🔽

Multi-select status filter on Proposals & Emails, Expired now included

The Proposals & Emails panel now lets you filter by more than one status at a time. Expired proposals are also exposed for the first time — useful for tracking stores that had a proposal fall through and need a follow-up.

Proposals
🔢

Tab counts show real work, and the sidebar badge counts actual problems

Inventory tab counts now reflect real items waiting for attention rather than a raw send total. The sidebar badge was also corrected — it now counts stores that have an actual issue, not the number of outgoing proposal sends.

Inventory
🚫

Switched-off products disappear cleanly from the CRM

When a product is turned off in Admin, it now disappears from all CRM surfaces — proposal views, inventory lists, and store detail — instead of lingering as a ghost entry with no inventory to back it up.

Inventory
🗺️ Map + routes
📍

Route panel reorganized: start your trip, add stops, then save

The route-building panel now flows in the order you actually work — pick a start, add stops along the way, and save when you're done. The old layout put the save action too early and buried the stop list.

Map
➕

Add stores to a route straight from the map pins

"Along the Way" is now properly gated so it only shows when a route is active, and you can add a store to the current route directly from its map pin without opening the full detail panel.

Map
💾

Saved routes tab: route-owner selector no longer clips under the tab strip

A layout bug was causing the route-owner dropdown on the Saved tab to get cut off by the tab bar. The selector now has proper clearance so you can see and use all the options.

Map
🔔 Alert Center + VMI
⏸️

Alerts can now be paused and resumed from the command line

Ops can now pause an Alert Center alert directly via CLI without going through the UI — useful for silencing a noisy alert during a deploy or an expected data gap — and resume it just as easily when things are back to normal.

Alert Center
🛡️

A paused alert stays paused — the outbox fallback no longer delivers it

There was a case where a paused alert could still get delivered through the outbox fallback path. That gap is closed — a paused alert is now paused everywhere, not just in the primary delivery route.

Alert Center
🛒

VMI intro is rep-authored when there's no register data to pull from

When a store doesn't have POS register data available, the VMI builder now generates a rep-written intro rather than leaving a blank or pulling from missing fields. The builder also records what the rep actually saw at the time, so the context is preserved.

VMI
📱 Dashboard + nav
🔢

Sidebar counters visible at every screen width, portal inbox fully counted

The sidebar counters were previously hidden at certain viewport widths. They now show at every size, and the portal inbox count is complete — it includes all pending items, not just the ones that fit the previous cap.

Navigation
💤

VMI reorder snooze added to the sidebar

Reps can now snooze a VMI reorder reminder directly from the sidebar counter without navigating into the full VMI flow. Less friction for a task that comes up constantly.

Navigation
📐

Compact CRM layout and consistent spacing restored

A regression had loosened the CRM's compact density, making rows taller and spacing uneven compared to the intended design. Both are corrected — the layout is back to the tight, consistent rhythm reps expect.

⚙️ Behind the scenes
  • Node 24.21.0 LTS standardized across CRM, MCP, and OpenClaw; the MCP package is now engine-strict to catch version mismatches early.
  • Sentry: FirebaseError code is now stamped in beforeSend where it survives the Dedupe plugin — errors were being grouped as generic FirebaseError instead of by specific code.
  • Analytics: Samples Given Out tooltip total was undercounting stacked segments — calculation corrected at the source.
  • Store detail: samples correctly excluded from the Analytics Product Breakdown (they were inflating product-level numbers).
  • Dashboard truncation reporting now says what was dropped and how much, not just that a cap was reached.
  • HIG audit completed across the consumer site and Shopify editorial preview — accessibility and spacing findings addressed.
  • MCP tool descriptions trimmed and self-explanatory reads marked so the tool list is easier to scan.
  • Dependency updates: vitest 5.0, Playwright 1.63, Sentry Node 10.73, Firestore client, resend 6.26, svix 2.3, hono — all across CRM and cloud functions.
  • Shopify editorial preview: MWAH trademark aligned with the wordmark and theme sources captured from the audited unpublished state.
