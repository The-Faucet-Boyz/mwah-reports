⭐ Highlights
🚀

The Pipeline board was completely rebuilt — every open order is now a focused, actionable card with all the facts you need in one glance

The Pipeline view went from a flat list to a board designed around getting orders moving. Each order now shows as a floating card with the key facts labelled — store, flavor counts, limits, and delivery window — so reps can decide what needs attention without drilling in. KPI tiles sit at the top of each lane, and the board pages within a lane rather than collapsing everything into one long scroll. This is the biggest single-week change to the Pipeline surface in the CRM's history.

Pipeline
👻

Pearanormal Activity launched on gimmemwah.com — the new flavor has its own page, store locator layer, and campaign banner

The site's newest flavor went live this week with a full launch: a product detail page with campaign banner and slime/glow effects, a dedicated flavor layer on the store locator showing which stores carry it (or have it on order), and flavor navigation updated across the products listing. Customers can now find Pearanormal at their nearest retailer directly from the site.

⚙️ Behind the scenes
  • Three CRM releases in one day (v102.50, 51, 52) — all on September 23 — covering a packed week of pipeline, fulfillment, and analytics changes.
  • Shared design-system primitives and a complete component library landed in the CRM, establishing a single token source across every surface.
  • Performance work in the CRM: journey timing added, store data prefetched before navigation, and a boot shell now shows the real UI chrome with a shared spinner during load.
  • Map coverage pins now show sales/day rate inline; stores without a recent sync are faded so reps can instantly see which data is fresh.
  • Inventory: POSaBIT flavor arrays now aligned by flavor code to fix a comparison bug where products were being matched in the wrong order.
  • Website: rate-limit bucket-cap check moved to O(1) — no more scanning all IP keys on every new signup request.
  • Website: the Apps Script signup poller now throttles alerts per scheduled job rather than across a shared global slot, preventing alert storms from one noisy job from silencing others.
  • Store locator feed now has an automated health monitor — if the public feed looks wrong (empty, malformed, or stale) an alert fires automatically.
  • Resend 6.28.1, @sentry/node 10.75.1, googleapis 181.0.0, firebase-functions 7.4.0, and BigQuery client bumped across CRM functions and MCP.
  • Latte Lover returned to the upcoming releases list in both registry copies after a mis-classification was caught.
