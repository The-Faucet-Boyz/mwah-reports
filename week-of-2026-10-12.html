⭐ Highlights
🔗

POSaBIT store mapping is now a real workflow — approve or reject matches right from Slack, without opening the CRM

When a POSaBIT store needs to be matched to a CRM account, the bot now sends an approval card in Slack with the current CRM name, the POSaBIT name, and one-click Accept or Reject buttons. Decisions are applied immediately. A new dedicated admin page consolidates all pending mappings in one place, and mapping health alerts have been cleaned up so only actionable issues come through.

POSaBIT
🏪

Inventory got a top-to-bottom rethink — a Needs Attention toggle, per-product By Store drill, and a "Went dark" view

The old category tabs are gone. Inventory now opens with a single Needs Attention toggle that surfaces only the stores requiring action. The By Store drill-down now focuses on one product at a time so the list stays scannable. And a new "Went dark" view flags stores that had recent POSaBIT data but have gone quiet — making it easy to spot coverage gaps before they become a relationship issue.

Inventory
🏪 Stores + compliance
📋

Reseller Permit status is now visible on the stores list and in the side panel

A new Reseller Permit column on the stores list shows each store's current permit status at a glance. The store side panel also gained permit and UBI rows, and an alert fires when a permit needs attention — so reps always know before walking in the door.

Stores
⚖️

Tribal permit exemptions, sales overrides, and Auto-pending corrected

A set of compliance and pipeline fixes landed together: tribal permit exemption logic now applies correctly, sales overrides work as expected, and the Auto-pending state for orders behaves consistently.

Orders
💰

POS Price column is off by default — hover the header for context

The POS Price column on the stores list is now hidden by default to keep the view cleaner. A hover legend on the column header explains what it shows and how to enable it when you need it.

Stores
📦 Inventory + VMI
🔍

By Store drill-down now scopes to one product, with a consistent sort chevron across the CRM

Drilling into a store in the Inventory By Store view now focuses on a single selected product, keeping the list tight and readable. The sort chevron behavior was also unified across every table in the CRM.

Inventory
🤝

VMI proposals can be approved even when some flavors are sold out — units are reserved at approval

Previously, a sold-out flavor would block approval of a VMI proposal entirely. Now approval proceeds for the available flavors, and the reservation limit is locked at the moment of approval so the numbers don't drift before the proposal is fulfilled.

VMI
📊

Inventory dropdowns fixed; dense workspaces are now desktop-only

Several Inventory dropdown interactions were corrected, and the dense workspace layout is now restricted to desktop screens where it renders reliably — mobile gets the standard layout instead.

Inventory
🔄 Reconciliation
↩️

Sample returns now work in Reconciliation, and Slack alerts are clearer

Reconciliation previously couldn't process returns on sample orders. That's now supported. The Slack alerts for changed-after-booking issues were also rewritten to be more descriptive, so the team can act on them without having to open the CRM first.

Reconciliation
📑

GrowFlow line edits now show the original booked value alongside the current value

When GrowFlow has modified a line on a booked order, the Reconciliation view now shows both what was originally booked and what GrowFlow is reporting now — side by side — so it's clear exactly what changed and by how much.

Reconciliation
🗺️ Route + field
⏱️

Route visit durations are now calculated correctly, and the location-picker warning is fixed

Visit duration tracking in the route view had a calculation bug that made times appear longer than actual. That's corrected, and a spurious warning in the location picker that appeared under normal conditions has been removed.

Routes
📬

Slack order alerts now show the current order once, with changes clearly highlighted

Order-change Slack alerts were previously sending a before-and-after view that was hard to parse. They now show the current order state once, with only the changed lines called out — much easier to act on at a glance.

Alerts
🔧

Reorder builder and store modal now open in context — no more full-page navigation

The reorder builder and the store details modal now open inline within the current view instead of navigating away. This keeps your place in the list while you work through proposals or check store details.

Navigation
🛍️ Buyer portal
👤

Buyer profiles now show access history and offer shared account controls

Buyer profile pages were expanded to include the full access history for each account and a set of shared controls that ops and account managers can use to manage access without going through engineering.

Portal
📦

Full-pack enforcement tightened — buyers can no longer round down below a full pack

Portal checkout now enforces the packs-of-10 minimum without any buyer-side override path. Typed quantities are rounded up to the nearest full pack automatically.

Portal
⚙️ Behind the scenes
  • Three CRM releases in two days: v102.56 on October 8, v102.57 and v102.58 on October 9 — all covering stores, inventory, reconciliation, and POSaBIT work.
  • BigQuery scan costs cut significantly: unused indexes dropped, view column types corrected to eliminate cross-type joins.
  • Stuck-order sweep restored and function out-of-memory crashes fixed — background sweeps were silently disabled after a prior deploy.
  • Functions deploy guard added: the deploy now fails immediately if an exported function was registered but never initialized, preventing silent gaps in the live function set.
  • POSaBIT mapping admin page (/map-posabit) extracted from the main admin surface so mapping work has a dedicated, bookmarkable URL.
  • Admin work item counter now includes POSaBIT mapping tasks alongside the existing queue items.
  • Review audit write path fixed after a silent failure was found in the ops review workflow.
  • Dep wave: resend 6.32.0, googleapis 183.0.0, @google-cloud/firestore, firebase-functions 7.4.0, svix 2.6.2, vitest 5.0.3, and @modelcontextprotocol/sdk all bumped across Functions and MCP.
